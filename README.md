# LEIA in Rust

Somewhere around 1994 I worked at the Dutch research center CWI (Center for Mathematics an Information Science) as a graduate student researching algorithms for machine learning. My supervisor, Paul Vitányi, had just published a book on Kolmogorov Complexity with Ming Li. On the EuroColt conference on computational learning theory in Barcelona I briefly met Ray Solomonoff, one of the inventors of algorithmic complexity (independently of Kolmogorov and Chaitin) as well as one of the founders of the field of Artificial Intelligence.

Although algorithmic complexity describes an upper bound on the amount of information present in a given body of information, it is of purely theoretical interest, because whichever way you approach it, it is incomputable. That means, it is not just slow, any program that tries to compute it is either inaccurate or literally never stops.

I did stumble across a theoretical framework that deals with the extraction od information from data that is very close in spirit to algorithmic complexity that is organized around the Minimum Description Length principle (MDL) formulated by Jorma Rissanen. This framework presupposes a model class, possibly infinite, such that every model in the model class has a unique finite description. Every model is required to assign a probability to the possibility that a certain token is the next token given the sequence of preceding tokens. (By the way, that is exactly how generative A.I. works. An LLM is a model that assigns probabilities exactly this way. It is given the tokenized conversation so far and produces a token randomly according to the probabilities the model assigned to produce the next token until a token appears that tell it to show it to the user.) The MDL states that the best model to predict the next token is the model that minimizes the sum of the length description of the model and the length of the description of the sequence of tokens so far given that model.

What do we mean by "the length of the description of the sequence of tokens so far given a model". Well, information scientists have a long history of designing codes that minimize the description length of data based on statistical properties. An early version of this is the invention of Morse code. Morse counted the letters on a newspaper page. Then he divided the number of occurrences of each letter by the total number of letters on the page. That gave him the probability of each letter on that page and (assuming that that page was a good sample of English text) the probability of each letter in English. Then he constructed a code that minimized the number of dashes for text that had the same frequencies of letters. Another example of this is the method of zipping a file (which I won't describe here). So MDL says you can use any model as if it were a Zip-program. Given some data, you chose the model for which the length of the program for that model plus the length of the output file when you use that program to compress the data is shortest. (If there are multiple models that realize exactly the same minimum total description length, we use Occam's razor and choose the model where the description length of the model is shortest.) An important characteristic of MDL, in contrast to LLM's, is that the model can't be arbitrarily complex. Its description has to fit within a total description of the given data, the length of which is minimized.

I realized that the description length of the model that MDL chooses can be taken as the amount of knowledge that MDL can extract from the data based on the model class. So, given a sufficiently powerful model class it is possible to use changes in model description length as gain / loss values and use those changes to guide an algorithm to explore its environment to gain knowledge about it. The goal of LEIA is to realize such an algorithm. The point is that it learns expectations (in contrast to predictions) incrementally (as opposed preprocessing a lot of data to generate a model an then use that model in the wild) and autonomously (as opposed to supervised). So Learning Expectations Incrementally and Autonomously: LEIA learns.

# Stable approximation of probabilities

When learning a huge model incrementally, it is crucial that adding a new token to the data does not involve recomputing the entire model. One way to accomplish this is by cleverly approximate probabilities in a way they only change to be more precise when mode data becomes available. I implemented this in Haskell ([updateRationals in MDL.hs](https://github.com/jeroenvanmaanen/lexau-haskell/blob/6578cc0c1bcb5b4a8a5b71dcd10bf30fcef38b7a/src/LExAu/Distribution/MDL.hs#L385). I am currently rewriting this in Rust. The current implementation doesn't perform very well, but I stumbled across a [Youtube video](https://www.youtube.com/watch?v=IePrsH3gU_A) and a [Wikipedia page](https://en.wikipedia.org/wiki/Lowest_common_ancestor) that suggest a dramatic improvement in performance, if I manage to turn it into an algorithm that can maintain its data-structure incrementally.
